## 硬件映射

| 功能 | 连接 | 备注 |
|---|---|---|
| 屏幕 | ST7735 类，SPI：MOSI=38 / SCLK=37 / CS=34 / DC=36 / RST=35 / BL=33，160×128 | **必须裸 SPI**（见下） |
| 屏幕方向 | MADCTL=0x60（MX\|MV） | 匹配横屏 160×128 |
| 音频 | N32L403 协处理器，UART1 @460800，TX=GPIO3 / RX=GPIO0，**无 ESP 侧 I2S** | 模拟麦克风 + 板载功放 |

## 关键结论（踩过的坑，别再重复）

1. **显示必须用裸 `spi_master`**（`main/display/raw_spi_panel.cc`），
   **禁止创建 `esp_lcd_panel_io_spi` / `esp_lcd_panel_st7789`** —— 一旦创建，面板完全无反应，
   连同时创建的裸 SPI 设备也一起失效（两个设备抢同一个 CS）。
2. **播放不要发 WAV 头**。data 长度写 `0xFFFFFFFF` 会让 N32 判断"还在等数据"而不出声。
   直接按 ≤200 字节块写 `0x15`。
3. **录音命令是 `0x10 = 1`**（不是 2）。发 2 会得到统计随机的垃圾流（std≈70、过零率 0.55），
   历史上正是因为误用 2，把"垃圾流"当成"电平极低"，然后加了 `<<20` 把噪声削成方波。
4. **麦克风读帧里 `len == 0` 的空帧也要读掉那 1 字节校验和**，否则流永久错位 1 字节。
5. **播放结束必须调 `AudioCodec::EnableInput(false)`**。框架只在 `!codec_->input_enabled()`
   时才发 `EnableInput(true)`，不同步清标志 ⇒ 第二句永远没反应。
6. **输出采样率必须 24000**。写 22050 会"声音快、尖锐"，并且"说到一半就停"
   （按 22050 喂料比 N32 按 24000 消费慢，句中缓冲见底）。输入保持 22050。
7. **N32 有独立供电**，ESP32 复位不会复位它；启动时要主动发 `0x10 = 0` 归位，
   否则可能停在录音态 ⇒ 播放静音。
8. **N32 没有可配置的输入增益寄存器**（0x00–0x20 全表读回验证，0x02–0x0F 全 0）。
9. **屏幕颜色**：MADCTL(0x36) 必须是 **0x60**（MX|MV，**BGR=0**），并且 RGB565 像素必须
   **高字节在前**（buf[0]=p>>8; buf[1]=p&0xFF）。发低字节在前会红蓝对调 ⇒ 整屏偏紫/水红。
   与出厂 MicroPython 驱动 `_pushcolor()`（`colorData[0]=aColor>>8`）一致。
   这套值是靠"8 组合枚举 + 人眼判定"实验定死的，别再靠推理改。

## 按键映射

| 操作 | 行为 |
|---|---|
| A 短按 | 对话开关；启动阶段按任意键 = 进配网 |
| A 长按 | 音量 −10 |
| B 短按 | 音量 +10 |
| C 短按 | 音量 −10 |
| D 短按 | 静音 / 恢复（0 ⇄ 70） |
| D 长按 | 进入 Wi-Fi 配网（AP + `http://192.168.4.1`） |

> 官方固件没有 `EnterWifiConfigMode` 入口（只能靠"连不上 Wi-Fi 自动进配网"）；
> 这里通过 `WifiBoard::EnterWifiConfigMode()` 补上了，是有意增强。
